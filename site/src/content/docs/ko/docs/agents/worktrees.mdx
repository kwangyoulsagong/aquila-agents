에이전트 두 개가 같은 체크아웃을 고치면 서로 부딪혀요. **git 워크트리**를 쓰면 같은 저장소에서 에이전트마다 폴더와
브랜치를 따로 가질 수 있어요. 한 프로젝트에서 여러 에이전트를 동시에 돌리고, 브랜치별로 따로 리뷰할 수 있어요.

Aquila는 워크트리를 저장소 옆에 만들어요.

```text
~/code/shop            ← 원래 체크아웃
~/code/shop-wt/feat/login
~/code/shop-wt/fix/cart
```

메인 워크트리 기준으로 `../<저장소>-wt/<브랜치>`예요.

<Shot id="worktree" caption="워크트리에서 열기: 브랜치를 적고 에이전트를 골라요." />

## 새 워크트리에서 세션 열기

<Steps>

1. 탭 바의 **+**를 우클릭 → **워크트리에서 열기…**, 또는 <kbd>⌘K</kbd>에서 **워크트리에서 열기**를 실행해요.

2. 브랜치 이름을 적어요. 예: `feat/login`. 적는 동안 로컬 브랜치를 추천해 줘요.

3. 칸 아래 줄에서 무슨 일이 어디서 일어날지 확인해요.
   - **새 브랜치 (…에서)** — 없는 브랜치라 새로 만들어요.
   - **기존 브랜치** — 있는 브랜치를 새 워크트리에 체크아웃해요.
   - **이미 있는 워크트리** — 그 브랜치가 이미 어딘가에 체크아웃돼 있어서 그 폴더를 그대로 써요.

4. **에이전트**(Claude, Codex, 셸 중 하나, 프로젝트 기본 에이전트가 먼저 골라져 있어요)를 고르고 **열기**를 눌러요.

</Steps>

탭에 브랜치 이름이 보이고, 패널 머리, 명령 팔레트, 알림에도 나와요. git이 거절하면(예: 잘못된 브랜치 이름) git의
오류 메시지를 창에 그대로 보여 줘요.

새 브랜치는 프로젝트 설정의 **기본 브랜치**에서 시작해요. 비어 있으면 지금 브랜치에서 시작해요.

## 이미 있는 워크트리에서 세션 열기

- 탭 바의 **+**를 우클릭 → **워크트리** → 브랜치 → Claude, Codex, 셸 중 하나.
- 또는 <kbd>⌘K</kbd>: 지금 프로젝트의 워크트리마다 "Claude · feat/login" 같은 항목이 떠요.

직접 `git worktree add`로 만든 워크트리도 저장소에 연결돼 있으면 똑같이 열 수 있어요.

## `.env` 같은 무시된 파일 복사하기

새 워크트리에는 추적되는 파일만 있어서 `.env` 같은 파일이 빠져요. 저장소 루트의 `.worktreeinclude`에 복사할 파일을
gitignore 문법으로 적어 두세요.

```txt title=".worktreeinclude"
.env
.env.local
config/secrets.json
```

Aquila가 워크트리를 만들 때 메인 워크트리에서 맞는 파일을 복사해요. git도 무시하는 파일만 복사하고, 이미 있는 파일은
덮어쓰지 않아요.

## 새 워크트리마다 셋업 실행하기

새 체크아웃에 필요한 다른 작업(의존성 설치, 코드 생성 등)은 **프로젝트 설정…**의 **셋업 스크립트**에 적어요. 새
워크트리에서 에이전트보다 먼저 한 번, 눈에 보이게 실행돼요. 스크립트가 실패해도 에이전트는 시작돼요.

<Aside type="tip" title="워크트리마다 포트">
  프로젝트 설정에 **포트 시작 번호**를 넣으면 세션이 `PORT` 변수를 받고, 워크트리마다 10씩 늘어나요. 두 브랜치에서
  dev 서버를 띄워도 포트가 겹치지 않아요.
</Aside>

## 워크트리를 따라가는 것

포커스된 탭이 워크트리에서 돌고 있으면 이 패널들은 메인 체크아웃이 아니라 그 워크트리를 보여 줘요.

- [변경사항 패널](/ko/docs/agents/changes-panel/) (diff, 스테이지·되돌리기)
- [미리보기](/ko/docs/agents/preview/) (그 워크트리의 주소와 기억한 URL)
- [Run 슬롯](/ko/docs/agents/run/) (그 워크트리의 명령과 로그)

앱을 다시 열면 워크트리 탭은 그 워크트리에서 다시 열려요. 폴더가 없어졌으면 그 탭은 빠져요.

## 워크트리 정리하기

<Steps>

1. 탭 바의 **+**를 우클릭 → **워크트리 정리…**(또는 <kbd>⌘K</kbd> → **워크트리 정리**).

2. 워크트리마다 **병합됨**·**병합 안 됨**, **변경 있음**, **탭에서 사용 중**이 표시돼요. 병합됐고 깨끗하고 열려 있지
   않은 워크트리는 **추천**이 붙어요.

3. 지울 워크트리에서 **삭제**를 누르고 한 번 더 확인해요. 깨끗하고 탭에서 쓰지 않는 워크트리는 모두 지울 수 있어요.

</Steps>

<Aside type="note" title="삭제하면 일어나는 일">
  `--force` 없이 `git worktree remove`만 실행해요. 커밋하지 않은 변경이 있는 워크트리는 실수로 지워지지 않아요. 폴더만
  지워지고 **브랜치와 커밋은 남아요**.
</Aside>

워크트리는 로컬 프로젝트에서만 돼요. SSH 호스트의 프로젝트에서는 쓸 수 없어요.
